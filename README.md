## Лабораторная работа №6: CI/CD

Workflow `.github/workflows/deploy.yml` запускается при push в `main`, при Pull Request в `main` и вручную через вкладку Actions.

1. Устанавливает зависимости командой `npm ci`.
2. Проверяет `index.html` с помощью HTML-Validate (`npm run lint:html`). Используется набор правил `html-validate:standard` для проверки HTML, без требований к оформлению кода.
3. Подготавливает статические файлы в `_site` и загружает артефакт GitHub Pages.
4. Публикует сайт только после успешного выполнения задания `build`. При ошибке проверки публикация не выполняется. Для Pull Request выполняется только проверка и подготовка файлов.

Проверяется основная страница `index.html`. Файл `deepseek.html` сохранён как исходный вариант из предыдущей работы: он копируется без изменений и не входит в область проверки HTML.

Индивидуальный проект: проверка HTML перед публикацией и индикатор результата workflow в начале этого README. Значок отражает результат всего процесса, включая публикацию; до первого запуска результат может быть недоступен.

## Локальная проверка

Требуется Node.js 24 и npm:

```sh
npm ci
npm run lint:html
```

## Включение публикации

В настройках репозитория откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**. После отправки файлов в `main` откройте **Actions → Deploy static site** и дождитесь успешного завершения заданий `build` и `deploy`.

## Проверка автообновления и материалы отчёта

Для демонстрации нужны два отдельных push: первый публикует workflow, второй содержит видимую правку страницы. До второй правки сохраните скриншот сайта. После следующего успешного запуска обновите страницу и сделайте скриншот результата. Изменение текста для этой демонстрации следует согласовать отдельно.

Сохраните не менее 5–6 скриншотов:

1. Файлы репозитория, включая `index.html` и `style.css`.
2. Настройки Pages с источником GitHub Actions.
3. Содержимое `.github/workflows/deploy.yml`.
4. Успешный запуск собственного workflow и шаг Validate HTML.
5. Сайт до изменения.
6. Сайт после автоматического обновления.
7. Значок статуса в README.

В отчёте укажите цель и задачи, ссылки на репозиторий и сайт, пояснения к скриншотам, описание индивидуального проекта, вывод о полученных навыках и фактически возникших проблемах, список источников. Тему индивидуального проекта методичка предлагает предварительно согласовать с преподавателем.

В методичке также есть упражнение с Vercel и сравнение двух способов публикации. Оно выполняется отдельно при необходимости; данная конфигурация использует GitHub Pages.
